## 1. 产品概述

### 1.1 产品定位

一款面向求职者的单页 Web 工具：上传简历（PDF/文本）、粘贴岗位 JD，一键获得 AI 驱动的匹配分析。个人自用 + 面试演示场景。

### 1.2 目标用户

求职者（个人使用），优先覆盖互联网/技术岗位。

### 1.3 核心价值

- 量化衡量自己与目标岗位的匹配程度
- 识别技能短板，获得可操作的补足建议
- 面试演示时可作为个人项目展示

### 1.4 后续拓展方向（本版不实现，设计预留）

- **简历优化**：针对特定岗位自动优化简历表述
- **面试题预测**：基于 JD 和行业生成可能面试题

## 4. 匹配算法设计

### 4.1 五维度与权重

| 维度 | 权重 | 打分逻辑 | 说明 |
|------|------|----------|------|
| 项目经验匹配 | **35%** | 语义相似度：简历项目描述 vs JD 工作内容。时间复杂度、规模、角色匹配 | 社招核心指标——实际做过什么比技能列表更有说服力 |
| 技术技能匹配 | **28%** | 语义相似度：JD 技术栈 vs 简历技能，交叉验证项目描述中是否实际使用 | 技能标签可解释空间大，需结合项目描述交叉验证 |
| 领域/行业匹配 | **15%** | 语义相似度：简历行业背景 vs JD 业务领域 | 同领域经验减少 onboarding 成本 |
| 软实力匹配 | **12%** | JD 要求（团队管理、跨部门协作、项目管理）vs 简历信号 | 社招关注"带过人吗""主导过项目吗""跨部门协作过吗" |
| 学历背景匹配 | **10%** | 达标基准制：不达标→0-20 分+额外惩罚；达标→70-100 分按专业相关性评分 | 社招原则：达标即可，不做过度区分 |

### 4.2 总分公式

```
总分 = 项目经验×0.35 + 技术技能×0.28 + 领域×0.15 + 软实力×0.12 + 学历×0.10
```

每维度 0-100 分，加权求和 = 0-100% 综合匹配度。

### 4.3 学历基准线机制

- **不达标**（JD 要求硕士，简历为大专）：该项 0-20 分，总分额外扣 5%
- **达标**（简历学历 ≥ JD 要求）：该项按专业相关性给 70-100 分

### 4.4 分析生成逻辑

| 分析类型 | 生成方式 | 具体逻辑 |
|----------|----------|----------|
| 核心优势 | DeepSeek 生成 | 按维度找出最高匹配点，基于简历与 JD 的实际交集、语义相似度高的具体条目 |
| 短板分析 | DeepSeek 生成 | 按维度找出最大差距点，优先关注 JD 中"必须"条件的缺失，标注对匹配值的影响 |
| 技能补足建议 | DeepSeek 生成 | 针对每条短板给出 2-3 步具体学习路径（推荐课程/书籍/实践项目） |
| 综合评语 | DeepSeek 生成 | 80-150 字总结，概括匹配全貌和关键发现 |

## 6. DeepSeek API 设计

### 6.1 调用规格

```
Endpoint: POST https://api.deepseek.com/v1/chat/completions
Model: deepseek-chat
Temperature: 0.3
Response Format: {"type": "json_object"}
Authentication: Bearer <VITE_DEEPSEEK_API_KEY>
```

### 6.2 Prompt 模板

```
你是一个专业的简历-岗位匹配评估系统。你的任务是分析候选人与岗位描述的匹配程度，并以严格的JSON格式输出结果。

## 评估维度与权重
- 项目经验匹配 (35%): 实际项目经历与JD工作内容的相似度、复杂度匹配、规模匹配
- 技术技能匹配 (28%): JD所需技术栈与候选人技能的重合度，需交叉验证项目描述中是否实际使用
- 领域/行业匹配 (15%): 候选人过往行业经验与目标岗位业务领域的契合度
- 软实力匹配 (12%): 领导力、沟通协作、项目管理等信号（社招重点关注是否带过团队、主导过项目）
- 学历背景匹配 (10%): 学历层次达标为基准线，达标后结合专业相关性评分

## 说明
- 优势: 选取匹配度最高的3-5个具体点，基于简历与JD的实际交集
- 短板: 选取差距最大的3-5个点，优先关注JD中"必须"条件的缺失
- 技能补足建议: 针对短板给出具体、可操作的学习路径（推荐课程/书籍/实践项目）

## 输出（严格JSON，无其他内容）
```

| 部分 | 预估 Token |

## 7. UI 设计

### 7.1 布局方案

采用**不对称紧凑单页布局**（方案 3）：

- **顶部**：标题栏 + "示例数据"标签（匹配后隐藏）
- **输入区**：简历卡片（PDF上传/文本输入Tab切换）与 JD 卡片左右并排，各占 50% 宽度
- **操作区**：居中"开始匹配分析"按钮
- **结果区**：三列不对称布局
  - 左窄列：综合评分环形图 + 综合评语
  - 中列：五维雷达图（维度名和分数直接标注在顶点外，无独立图例模块）
  - 右宽列：优势/短板/建议三张卡片纵向堆叠

### 7.2 交互状态

| 状态 | 表现 |
|------|------|
| 初始 (Demo) | 输入区预填示例内容，结果区展示 Demo 结果，顶部"示例数据"标签可见 |
| 用户输入中 | 用户可以修改简历和 JD 内容 |
| 匹配中 | 按钮显示加载动画（spinner + "分析中..."），结果区保留旧数据或显示骨架屏 |
| 匹配完成 | 结果区平滑替换为真实数据，"示例数据"标签消失 |
| 匹配失败 | 错误提示 + "重试"按钮 |

## 8. 错误处理

| 场景 | 处理方式 |
|------|----------|
| 简历或 JD 为空时点击匹配 | 按钮上方显示行内错误提示："请上传简历并粘贴岗位描述"，阻止 API 调用 |
| PDF 解析失败 | 提示用户尝试粘贴文本方式 |
| PDF 文件过大 (>10MB) | 前端校验，提示文件过大 |
| API Key 未配置 | 提示配置 VITE_DEEPSEEK_API_KEY |
| API 超时 (30s) | 提示超时 + 重试按钮 |
| API 返回非 JSON | 兜底解析 + 降级展示原始文本 |
| API 返回 4xx/5xx | 展示对应错误信息 + 重试按钮 |
| 网络断开 | 提示网络错误 |

## 12. 开发工作流

### 12.1 Git 提交规范

每完成一个可独立验证的功能单元，立即提交：

```
[可独立验证的功能单元] → git add + git commit → 继续下一个单元
```

**提交粒度示例：**
- 项目脚手架搭建（Vite + React + Tailwind）
- PDF 解析模块完成
- 输入区组件（ResumeCard + JdCard）完成
- API 服务层完成
- 结果区组件（ScoreRing + RadarChart + AnalysisCards）完成
- Demo 数据集成完成
- 错误处理与空输入校验完成

### 12.2 忽略文件

`.gitignore` 需包含：

```
node_modules/
dist/
.env
.env.local
.superpowers/
*.log
.DS_Store
```
